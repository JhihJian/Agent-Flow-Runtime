# Flow 引用执行设计

一条 Flow 的节点可以引用另一个 Flow 执行。父节点通过显式 `inputs` 启动独立子 Run，子 Run 走完自己的路径后，父节点按终态继续路由。

## 1. 语义

| 问题 | 决策 |
| --- | --- |
| 引用方式 | 运行期嵌套执行独立子 Run，父图保持自身结构 |
| 输入 | 只传显式 `inputs`，名称必须是子 Flow 已声明的全局变量 |
| 输出 | 只返回父节点成功结果中声明的下一跳变量 |
| 子 Flow 失败 | 双结果边走 `已失败`，无结果边则父 Run 失败 |
| Agent 归属 | 子 Run 独立绑定 Agent，首个 Agent 动作必须是 `新建Agent` |
| 恢复归属 | 子 Run 只随父 Run 恢复 |

子 Run 使用自己的全局变量和运行状态，不复制父 Flow 的完整变量快照，也不自动回传内部全局变量。节点引用、事实提交、观测订阅和 Agent 绑定仍按 Run 隔离。

## 2. 语法

动作标记为 `执行Flow`，代码块只包含 `flow` 与可选的 `inputs`：

```json
{
  "flow": "release-check",
  "inputs": {
    "项目": "{var.项目}",
    "版本": "{input.版本}"
  }
}
```

`flow` 是兄弟包目录名。`inputs` 是 JSON 对象，值中的 `{var.xxx}` 与 `{input.xxx}` 按父节点上下文替换。整值引用保留 JSON 类型，内嵌引用转换为文本。没有默认值的子 Flow 全局变量必须显式提供。

父节点出边二选一：

- 无结果边直连：子 Run 成功后固定流转，失败时父节点按执行失败处理。
- 恰 `已完成`、`已失败` 两条结果边：子 Run 终态由运行时选择。

显式输出示例：

````markdown
## 执行发布检查

```执行Flow
{
  "flow": "release-check",
  "inputs": { "项目": "{var.项目}", "版本": "{input.版本}" }
}
```

### 已完成

| 变量 | 含义 |
| --- | --- |
| 检查结论 | 子 Flow 返回的发布检查结论 |

子 Flow 已完成，下一节点通过 `{input.检查结论}` 读取结论。

### 已失败

子 Flow 执行失败，失败详情保存在运行记录和执行证据中。
````

无结果边节点没有三级结果标题，因此不声明下一跳输出。输出不是子 Run 最后一次节点结果或全局快照的自动注入。

## 3. 输出与状态

父节点的统一结果只包含 `result` 和可选的 `variables`：

```json
{
  "result": "已完成",
  "variables": { "检查结论": "通过" }
}
```

子 Flow 只能返回父节点成功结果中声明的下一跳变量。父 Flow 如需长期保留输出，由父节点显式写入父 Flow 已声明的全局变量。子 Flow 失败不产生下一跳变量，错误通过子 Run 标识及执行证据追踪。

## 4. 加载与执行

引用只能指向兄弟包：按父包上一级目录定位 `<flow>/FLOW.md`。加载父定义时递归加载引用闭包和资源，自引用或环引用在加载期拒绝。组合指纹包含子 Flow，恢复时拒绝父子文件漂移。

执行过程：

1. 渲染父节点 `inputs`，按子 Flow 变量声明校验启动输入。
2. 创建独立子 Run，共用存储、Agent 运行模型、命令执行器和观测发布器。
3. 子 Run 到达终态后，选择父节点结果边并校验输出变量。
4. 原子保存父 NodeRun 完成、全局变量更新、下一跳输入和路由事实。

子 Run 记录 `parentRunId`、`parentNodeRunId`，父 NodeRun 记录 `childRunId`。子节点事实只写入子 Run。

## 5. 恢复与验收

父 NodeRun 已完成时沿用其已提交变量与路由。父节点中断且子 Run 已终态时补全父节点事实；子 Run 仍在运行时，先递归恢复子 Run。子 Run 不能直接恢复。

验收应覆盖：兄弟包缺失和环引用拒绝、显式输入校验、默认值、父子状态隔离、输出声明约束、失败无下一跳变量、父 Agent 绑定保留、文件漂移拒绝，以及子 Run 完成与父节点提交之间的崩溃恢复。

格式与作用域分别以 [Flow 规范](flow-spec.md)和[变量设计](flow-variables-design.md)为准。
