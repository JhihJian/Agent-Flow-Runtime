# Flow 运行记录 Web 展示设计

## 1. 定位

Web 展示模式是 Flow Runtime 的只读运行观察站。它面向需要持续跟进运行、定位失败节点、查看 Agent 交互和命令输出的本地可信用户。

Web 页面展示一次具体 Run 的持久化事实和受权限控制的执行依据。它不提供结果提交、路由选择、恢复、重试、停止或命令重放操作。

```text
Browser
  -> Web 观察宿主
      -> FlowRuntime
          -> FlowRunInspector
          -> FlowObservationPublisher
```

浏览器不直接持有 `FlowRuntime`、`RunStore`、`FlowCoordinator`、`.pi/flow-runs.json` 或 Pi 会话读取器。Web 观察宿主负责请求授权、字段脱敏、快照读取和实时连接生命周期。

## 2. 页面层级

```text
运行中心
  -> 近期 Run 列表
  -> 选择一次 Run

Run 详情
  -> 顶部运行摘要
  -> 三栏事实浏览
  -> 按需节点证据
```

运行中心解决“查看哪一次运行”，Run 详情解决“这次运行发生了什么”，节点证据解决“节点运行期间有哪些可追溯内容”。

## 3. 运行中心

运行中心采用密集列表而不是卡片墙。默认按最近状态变化排序，首屏优先展示正在执行、失败和中断的 Run。

每行显示：

| 信息 | 展示口径 |
| --- | --- |
| Task 摘要 | 单行脱敏摘要 |
| Flow | 名称或 `flowId`，附版本短标识 |
| 主状态 | 执行中、已完成、已失败、已中断 |
| 阶段 | 正在执行节点、正在路由、等待并行、已结束 |
| 位置 | 当前节点、等待分支或最后位置 |
| 时间 | 开始时间、最近更新、持续时间或完成时间 |
| 风险 | 错误摘要、恢复标记、历史不完整标记 |
| 标识 | Run ID，作为次级复制信息 |

快速筛选：全部、执行中、需关注、已结束。需关注包含失败、中断、错误摘要和 `legacy` 历史。

列表不展示完整 Task、Prompt、Agent 对话、命令输出、工作目录、会话路径或完整 Flow 指纹。

## 4. Run 详情

### 4.1 顶部摘要条

顶部固定显示：

```text
Task 摘要
Flow / 版本          Run ID
主状态               阶段
当前或最后位置       开始、结束与耗时
历史完整性           最后确认水位与页面连接状态
```

Run 生命周期状态、当前执行阶段和 Web 连接状态分别展示：

- Run 状态表示 Flow 是否完成、失败或中断。
- 阶段表示节点执行、路由或并行等待。
- 页面连接状态表示浏览器能否接收刷新通知。

页面断线不会被展示为 Run 中断。

### 4.2 三栏事实浏览

桌面端使用三栏布局：

```text
左栏                 中栏                         右栏
事实导航             实际执行时间线               事实检查器
```

左栏提供访问概览和时间线目录：节点访问次数、返工次数、并行轮次、恢复次数、失败节点和事实类别筛选。

中栏是默认工作区，按 Run 内事实序号展示：

```text
节点访问 -> 路由选择 -> 并行轮次 -> 恢复 -> Run 终态
```

右栏显示当前选中事实的结构化详情和证据入口。

移动端降级为单栏：摘要、时间线、事实检查器、节点证据。左栏导航收纳为可打开的目录，右栏检查器改为底部抽屉或详情区。

## 5. 事实时间线

时间线以 `FlowRunHistory` 为权威来源，不以当前 Flow 文件反推历史。

### 5.1 NodeRun

每次节点访问都是独立条目：

```text
分析 #1  已中断
恢复      Agent 重试
分析 #2  已完成 -> 已分析
```

相同 `nodeRef` 的多次访问保留访问编号和 NodeRun 关联。返工、循环和恢复都不能压缩成单个节点状态。

### 5.2 RouteDecision

路由以独立事实显示：

```text
来源：验证 #2
结果：返工
目标：修改
```

结果名只说明 Flow 选择的边，不自动解释为业务成功或失败。

### 5.3 ParallelRound

并行轮次是可展开的复合事实：

```text
并行检查 #2  等待汇合
  测试       已完成 -> 已执行
  静态检查   执行中
  汇合       尚未开始
```

同一并行入口的不同轮次按 `parallelRoundId` 分开显示。分支完成顺序、分支归属和汇合输入同时保留。

### 5.4 Recovery

恢复条目连接旧 NodeRun、恢复策略和新 NodeRun：

```text
验证 #1      已中断
恢复         retry_agent
验证 #2      执行中
```

命令节点未自动重放时明确显示 `fail_command` 及其终态原因。

## 6. 节点检查器与详细内容

右栏的节点检查器分为三个层级。

### 6.1 概览

默认显示：

- 节点名称、NodeRun ID 和访问编号。
- 动作类型、状态、开始/结束时间和耗时。
- 进入来源、路由关系、所属并行轮次和恢复前驱。
- 输入摘要、结果名、错误类别和错误摘要。
- 会话/交互引用是否可用、命令输出是否可查询。

### 6.2 Agent 运行过程

用户明确点击“查看完整依据”后，Web 宿主请求该 NodeRun 的 `inspectNodeEvidence`。

Agent 节点以消息时间轴展示：

```text
用户提示
助手消息
工具调用结果
助手消息
```

每条消息按角色、顺序和内容区分。长消息默认折叠，用户可展开单条内容。页面不默认加载其他 NodeRun 的会话，也不提供脱离 Run 的全局会话浏览。

### 6.3 命令运行过程

命令节点详情分为：

- 概览：执行状态、退出码、开始/结束时间和错误摘要。
- 标准输出：可滚动、可折叠的纯文本区。
- 标准错误：可滚动、可折叠的纯文本区。

命令退出码非零时，界面显示“命令执行已完成，业务结果为 failure”。执行器异常、命令中断和业务退出结果保持不同的状态表达。

完整 Task、Prompt、消息、stdout 和 stderr 由服务端按 NodeRun 授权后返回。浏览器端折叠或截断不作为安全边界。

## 7. 实时和断线

页面打开详情时：

```text
建立观察
  -> 读取历史快照
  -> 展示快照
  -> 收到更高水位事件
  -> 合并刷新请求
  -> 用新快照整体校正页面
```

`FlowObservationEvent`只提示“可能有新事实”，不直接改写页面时间线、节点状态或并行状态。

断线时保留最后确认快照，并显示：

```text
实时连接已断开
最后确认：sequence 23
Run 可能仍在继续执行
```

重连时重新校验访问权限、建立观察并读取新快照。页面不依据遗漏事件补造断线期间的过程。

当前 Publisher 是进程内尽力而为通知。Web 模式对外承诺“快照最终校正”，不承诺可靠过程审计或完整事件回放。

## 8. Web 宿主边界

Web 宿主是 Browser 与 `FlowRuntime` 之间的只读适配器。

它负责：

- Run 列表、Run 快照、节点证据和实时连接的身份校验。
- 将 Runtime 返回值转为浏览器可见的脱敏读模型。
- 对列表数量、分页、证据大小、并发订阅和重连频率实施限制。
- 以纯文本呈现 Task、消息、错误和命令输出，不将内容解释为 HTML。
- 记录证据访问审计，不复制证据正文。

它不负责：

- Flow 执行、节点结果提交、路径选择、Run 恢复或命令重放。
- 直接暴露 RunStore、Publisher、会话路径或 Pi 适配器。
- 将浏览器事件作为新的流程控制来源。

本地可信单用户模式可以使用本地会话授权。网络暴露或多用户模式需要服务端主体、Run 可见范围、证据授权、脱敏和访问审计契约。

## 9. API 视图

Web 宿主只暴露与展示对应的读操作：

```text
GET  /runs
GET  /runs/:runId
GET  /runs/:runId/node-runs/:nodeRunId/evidence
GET  /runs/:runId/observe
```

`observe`使用事件提示刷新，不承载历史重放。每个请求和每次重连都校验 Run 可见性；证据请求额外校验 NodeRun 和证据权限。

## 10. 不在首版实现的能力

- 静态 Flow 结构图。它需要 `flowId + flowVersion` 对应的历史 Flow 定义提供者。
- 跨 Run 路径对比。它需要版本对齐规则和列表聚合读模型。
- 可靠过程回放。它需要可授权的追加事件或过程证据流。
- 多租户、跨项目和公网部署。它们需要独立身份、租户、审计和保留策略。
- 重试、恢复、停止和命令重放按钮。它们属于独立运行控制契约。

首版 Web 只读观察站优先保证：能找到 Run、看懂事实路径、展开节点依据，并在实时通知丢失时用快照恢复正确状态。
