# Flow Authoring

## 目标

把任务方法写成可执行的通用 Markdown Flow。Flow 文件不能包含 Pi 专用字段、动作或工具名称。

## 创建步骤

1. 先判断是否已有相似 Flow。读取 `.md` 文件的 `description`，优先复用已有方法，避免复制一份语义相同的流程。
2. 为新 Flow 选择唯一文件名。文件名去掉 `.md` 后是 Flow 标识。
3. 只在文件开头写 `name` 和 `description` 元信息。
4. 设计少量工作节点。每个工作节点只做一个动作，并为每个可能结论设计一个结果名。
5. 使用一张 `flowchart TD` Mermaid 图连接 `start`、工作节点、`{{并行}}` 和 `finish`。
6. 为每个工作节点写同名二级标题、一个动作代码块、以及每条结果边对应的三级结果说明。
7. 需要并行时，只把自定义命令放在并行分支。让所有分支进入同一个自定义命令汇合节点，并在汇合节点的 `stdin` 中引用每个直接分支的结果。

## 动作规则

- `新建Agent` 创建本次 Flow 运行的 Agent。
- `复用Agent` 继续本次运行已绑定的 Agent。
- `执行自定义命令` 的代码块必须是 JSON 对象，包含非空 `command`，可选 `args` 字符串数组和 `stdin` JSON 值。
- `{outcome}` 只放在动作代码块中，表示当前节点输入。
- 汇合命令用 `{节点引用名.outcome}` 读取本轮直接分支的完整结果。这个引用必须是 `stdin` 中的独立 JSON 值。

## 检查清单

- 元信息只有非空 `name` 和 `description`。
- Mermaid 图恰有一张，且 `start` 只有一个去向、`finish` 没有去向。
- 所有工作节点可从 `start` 到达，并存在到 `finish` 的路径。
- 节点引用名、节点名称和结果名在规定作用域内唯一。
- 节点标题、动作标记、结果边和三级结果说明一一对应。
- 命令节点只有 `已执行` 结果边。
- 并行开始点有两个以上命令分支，所有分支进入同一个汇合命令节点。
- 汇合节点引用每一个直接分支的 `{节点引用名.outcome}`，不引用其他节点或历史轮次。

完整语法以 `docs/flow-spec.md` 为准。运行时会在 Flow 启动前执行结构检查，不能用 Agent 的专业判断替代结构检查。
