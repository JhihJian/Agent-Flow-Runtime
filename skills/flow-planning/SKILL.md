# Flow Planning

## 何时使用

在开始执行任务前，判断任务是否属于需要提前规划路径的复杂流程：

- 需要经过多个阶段，阶段之间有明确的先后关系。
- 需要根据检查结论决定通过、返工、循环或结束。
- 需要执行多个独立检查，再根据汇总结果继续判断。
- 任务会重复出现，值得沉淀为可复用的工作方法。
- 任务边界、门禁条件或返工范围尚不清晰，直接执行容易反复打补丁。

符合任一情况时，先使用本 Skill 规划工作路径，再开始执行任务。只有一个明确动作、没有判断分支、没有复用价值的一次性任务，通常不需要创建 Flow。

## 目标

把一次任务中稳定的工作方法沉淀为通用 Flow，让具体任务能够沿着清晰、可追踪、可复用的路径执行。Flow 应表达工作阶段、判断依据、结果去向和退出条件，不应记录某一次运行的临时状态。

Flow 不应包含任何特定宿主、平台、产品或 Agent 实现的专用字段和约定。运行环境如何承载流程属于运行时实现，不属于 Flow 方法本身。

## 规划过程

1. 先梳理任务目标、输入、阶段、依赖、完成标准和可能的失败路径。
2. 检查已有 Flow 的适用范围，优先复用工作方法相同的流程；只有方法确实不同才新建。
3. 识别必须由执行者判断的门禁，以及每个门禁的通过、返工和无法继续条件。
4. 识别可以独立执行的检查和需要汇总的结果，避免把互相依赖的工作错误地并行化。
5. 为每个阶段分配单一职责，控制流程规模，确保每一步都能说明做了什么、依据是什么、下一步是什么。
6. 为循环设计明确的退出条件和最大合理范围，避免流程只会反复返工而无法结束。
7. 阅读本 Skill 随附的 `reference/flow-spec.md`，严格按照其中的格式把规划结果写成 Markdown Flow。
8. 写完后再次对照内部规范检查结构、路径、动作、结果和数据传递，再开始执行。

## 设计原则

- 优先解决问题的共性，减少重复劳动和长期维护成本。
- 对重复出现的判断建立清晰门禁，对返工原因保留足够证据。
- 让结果内容传递事实、证据和待处理信息，让路径选择保持明确。
- 对无法继续改进的情况，明确记录检查范围、保留项和具体原因。
- 不把临时补丁、隐含状态或特定环境假设固化为通用方法。
- 已投入使用的 Flow 视为固定工作方法。方法发生变化时创建新文件，不悄悄改变已有流程的含义。

## 完成标准

规划完成前，确认：

- 这确实是值得预先规划的复杂长流程，而不是简单一次性动作。
- 工作阶段、门禁、返工路径和结束条件都已明确。
- 每个阶段职责清楚，流程没有不必要的特殊分支。
- 循环能够在可观察的条件下结束。
- 并行检查只用于真正独立的工作，并且结果有明确汇总方式。
- Flow 没有绑定特定宿主或平台。
- 已完整阅读并遵循 `reference/flow-spec.md`。

本 Skill 的完整 Flow 格式、动作定义、结果传递和结构校验规则，全部以随附的 `reference/flow-spec.md` 为准，不在本文件重复定义。
